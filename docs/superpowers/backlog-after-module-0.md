## Остатки модуля 1b (2026-10-14)

### Мессенджер: отложенные решения
- Срок запроса: обещанный в уроках 1.5 и 1.7 middleware `context.WithTimeout` для каждого запроса в 1b не сделан (строка 503 `timeout` в таблице ошибок ждёт его). В уроках об этом теперь сказано прямо.
- Ключи идемпотентности: фоновая очистка просроченных записей (сейчас запись лишь перезаписывается `Reserve` после TTL — формулировка «удаляются при обращении» неточна); сбой `Complete` оставляет ключ «в работе» до конца TTL (409 на 24 ч) — описать в ADR и решить в 2a (урок 1.12, модуль 2a/5).
- Пароли: перехеширование при смене параметров Argon2id (при входе, по параметрам в PHC-строке); проверка новых паролей по списку утёкших (k-anonymity HIBP); регистрация с некорректным именем всё равно считает полный хеш (абзац урока 1.13 о DoS говорит только о входе); `argon2id.parse` через `Sscanf` принимает хвост после чисел (`p=1xyz`).
- JWT: публикация ключей JWKS и ротация по `kid`; refresh-токены и отзыв; верификатор кладёт непроверенный `kid` в текст ошибки (`%q`) вопреки «не показывать непроверенные данные»; middleware не пишет в журнал причину отказа токена (истёк / подпись / аудитория); ADR-0003 «хендлеры не изменились» — преувеличение (`WWW-Authenticate`, новый `CreateToken`).
- Rate limiting входа и регистрации — модуль 6.7.
- Контракт и маршрутизатор расходятся: `HEAD` на GET-маршрутах (ServeMux отвечает сам) и `307` на путь с `//` не объявлены в контракте — их пропускает только терпимость валидатора `openapitest`; объявить или закрыть.
- `409 idempotency_in_progress` без `Retry-After`: стоит подсказать клиенту, через сколько повторить.
- Теги `m01-l11`…`m01-l13` сохраняют поведение до правок итогового ревью 1b (повтор сохранённого `415` при исправленном `Content-Type`, `?limit=0` → `200`, `/v1/users/me` без пользователя → `404`); уроки на этих тегах показывают старое поведение, тег `m01-l14` — новое.
- Курсор: `Decode` принимает ключи в другом регистре и дубли (смягчить «всё, чего он не пишет, — признак порчи» или сравнивать с повторной кодировкой); `cursor.MaxLen` (512) и `maxLength: 512` в контракте не сверяются тестом; `ListMessages` разбирает курсор раньше проверки членства (400 вместо 403) — нужен комментарий.
- `httpjson.DecodeError`: коды-литералы не привязаны тестом к реестру `problem`; поле `Status` больше никто не читает.
- Тесты: тесты адаптеров разбирают `request_id` и `detail`, но не проверяют их; подтест «некорректное имя» в use case auth идёт по той же ветке фейка, что «nobody».

### Инструменты курса
- `check:messenger`: `generatedFiles` ищет `gen` по абсолютному пути (счётчик раздуется, если репозиторий лежит в каталоге `gen`); проверка свежести `go generate` сравнивает рабочее дерево, а не git — строгой её делает только чистый checkout в CI (оставить комментарий).

### Глоссарий
- `salt.long` «Argon2id генерирует соль сам» — это делает обёртка; `at-least-once.long` «недостижимо дорогое exactly-once» — слишком сильно; `status-code.long` «остальные 4xx повторять бессмысленно» — абсолютно (401 после обновления токена, 409, 425).
- Ссылки без URL: черновик IETF Idempotency-Key, Use The Index Luke; атрибуция Клеппман гл. 11 не сверена.

### Визуализации
- Радиогруппы без roving tabindex и стрелок (`PaginationSandbox`, `IdempotencySandbox`); `IdempotencyView` — ключ `k-1` зашит в разметку; `JwtView` — сегмент заголовка красный (`--viz-error`), хотя красный везде значит «отвергнуто».
- `ProblemMapping`: подписи «один маппер на все источники», «type — это адрес» спорят с уроком; тексты `ROUTER_TEXT`/`DOMAIN_TEXT` — не настоящий вывод `Error()`, а урок 1.10 утверждает, что настоящий; придуманные тексты ошибки параметра oapi-codegen и `MaxBytesError`.
- `login-timing`: журнал показывает сырой `login=mallory` (чувствительный ввод в журнале); `RequestPipelineView` — `@container` меряет плеер, нужен `container-type` на `.pipe`; `term('Recover','middleware')` — подпись и определение расходятся.

### Контент уроков
- 1.8: «оборванный ответ 200» — на деле 200 с частичным телом и приклеенным JSON ошибки; Stripe pinning «при создании аккаунта» против «первого запроса» в цитируемом посте; Deep о дереве маршрутов (методы под узлом хоста, `matchingMethods` пробует `path+"/"`); комментарий `routeError` «по очищенному пути ничего не найдено» → «для этого метода»; два текста 401 (middleware и `caller`) не объяснены, у `user` нет проверки в `caller`.
- 1.9: «тип параметра → другая сигнатура метода» — на деле ошибка в месте использования; `Callout simplified` для проектного замечания (id как строка); `uuid.Parse` принимает и 32 hex без дефисов; выводы «contract-pipeline» сокращены и перенесены; в `TestErrorMapping` контекста `user` GET-строки шлют JSON-тело.
- 1.10: «`Code` — тип, а не строка, перепутать сложнее» — преувеличено (нетипизированные константы приводятся); «оба формата старше RFC 7807» — рекомендации Microsoft 2016 года моложе, формат — из OData v4 (2014).
- 1.11: `Callout simplified` для отступления от AIP-158; AIP «should coerce», а не «требует».
- 1.12: Telegram `RANDOM_ID_DUPLICATE` «явно неправильное использование» — без источника; «4xx окончателен» — обобщение для 4xx, зависящих от состояния (404, 409: повтор после изменения состояния получит старый ответ); не упомянут синтаксис значения sf-string из черновика IETF; «20 из 20» подан как доказательство атомарности, а тест этого не различает; «черновик требует» → «советует» (SHOULD).
- 1.13: номера глав Вернона, Эванса и Фаулера не сверены с книгами.
- 1.14: `alg: none` — ссылаться на RFC 7518 §3.6 / RFC 7519 §6, а не на 7515; «последние строки» — а показан весь регион.
- Сценарии `curl` уроков 1.7–1.13 сняты на своих тегах и на нынешнем коде без поправок не работают (пометки в уроках есть); при следующей правке API подумать о сквозном скрипте сценария, проверяемом в CI.
