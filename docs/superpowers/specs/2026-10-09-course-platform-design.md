## 1. Контекст и цель всего курса

**Для кого.** Для одного человека: Go-разработчика с опытом чуть больше года.
Цель — выйти на уровень Middle+/Senior в проектировании систем.

**Стек ученика:** Go, PostgreSQL, Docker, docker-compose, Git, Linux (Ubuntu), Redis, Kafka, Kubernetes.
С Kafka, Kubernetes и внутренним устройством PostgreSQL ученик знаком мало, поэтому их объясняем с нуля.

**Формат курса:**
- язык — русский, каждый термин поясняется (английский оригинал указывается рядом);
- теория опирается на признанные источники (см. раздел 7); материал излагается своими словами со ссылками на главы, книги не копируются;
- интерактивные пошаговые визуализации в духе AlgoMaster — обязательная часть, а не украшение;
- сквозной практический проект — мессенджер (аналог Telegram) на Go. Он растёт от монолита до распределённой системы в Kubernetes.

**Критерий успеха всего курса.** Ученик может:
- спроектировать систему уровня мессенджера, объясняя компромиссы каждого решения;
- реализовать ключевые части на своём стеке;
- пройти system design интервью.

## 4. Движок визуализаций

### 4.1 Принцип

Сценарий отделён от отрисовки:

```
Simulation (чистая функция)  →  Step[]  →  Player (управление)  →  Renderer (SVG)
```

### 4.2 Модель данных

```ts
interface Step<S> {
  state: S                 // полный снимок состояния системы на этом шаге
  highlight?: string[]     // id элементов, которые подсвечиваются
  caption: string          // пояснение на русском (может содержать термины)
  codeLine?: number        // строка в CodePanel, которая сейчас «выполняется»
}

// Режим «пошаговый разбор»: фиксированный сценарий
type Scenario<S> = () => Step<S>[]

// Режим «песочница»: действие пользователя → новые шаги от текущего состояния
type Simulation<S, A> = (state: S, action: A) => Step<S>[]
```

- `state` — полный снимок, а не дельта. Поэтому переход назад и прыжок на любой шаг тривиальны.
- Симуляции и сценарии — чистые функции без зависимости от Vue. Они тестируются отдельно.

### 4.3 Компоненты

**`Player`.** Получает `steps` и слот для рендерера. Умеет:
- кнопки ⏮ ◀ ▶ ⏭ и ⏯;
- скорость 0.5×, 1× и 2×;
- полосу прогресса с переходом на любой шаг;
- клавиши ← / → / пробел, которые работают только когда плеер в фокусе;
- блок пояснения к текущему шагу.

**`CodePanel`.** Показывает фрагмент кода с подсветкой синтаксиса и выделяет строку `codeLine` текущего шага.

**Рендереры.** Vue-компоненты на SVG. Получают `state` и `highlight` и рисуют их.
- Простые переходы делаются средствами Vue/CSS.
- Движение объектов по траекториям (например, «пакет летит по стрелке») — через GSAP.
- Если пользователь включил `prefers-reduced-motion`, анимации заменяются мгновенной сменой кадра.

### 4.4 Визуализации подпроекта 1

1. **`request-path`** (пошаговый разбор). Путь запроса «Отправить сообщение»:
   1. клиент → DNS;
   2. TCP/TLS;
   3. балансировщик;
   4. сервер приложения;
   5. БД;
   6. ответ клиенту.

   На каждом шаге: подсвеченный узел, «летящий» пакет, пояснение и накопленная задержка.
2. **`latency-scale`** (интерактивная шкала). Справочные задержки (L1, RAM, SSD, сеть внутри ЦОД, межконтинентальный запрос) в двух режимах:
   - реальные значения в логарифмической шкале;
   - «человеческий масштаб», где 1 нс = 1 с.

   Числа приводятся со ссылкой на источник и с оговоркой, что это порядки величин.
3. **`estimation-calculator`** (песочница). Ползунки: DAU, сообщений на пользователя в день, средний размер сообщения, коэффициент пика, срок хранения, коэффициент репликации. Вывод по шагам:
   1. средний RPS;
   2. пиковый RPS;
   3. объём в день и за срок хранения;
   4. входящий трафик.

   Каждая формула видна. Калькулятор используется в уроках 0.5 и 0.6.

## 5. Глоссарий и термины

Формат `glossary/terms.yaml`:

```yaml
wal:
  term: WAL (журнал предзаписи)
  en: Write-Ahead Log
  short: Журнал, куда изменение записывается до изменения самих данных; нужен для восстановления после сбоя.
  long: |
    Подробное объяснение в Markdown...
  links:
    - title: Клеппман, гл. 3
```

- **В тексте:** `<T id="wal">WAL</T>`. Термин подчёркнут; при наведении или фокусе показывается `short`, клик ведёт на страницу глоссария.
- **Несуществующий `id`** — ошибка сборки, а не молчаливый пропуск.
- **Страница глоссария** генерируется из YAML: сортировка по алфавиту, якорь у каждого термина.

- `npm run build` проходит без ошибок и предупреждений о битых ссылках и терминах.

- Все термины модуля 0 имеют записи в глоссарии.
