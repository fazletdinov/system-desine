## 1. Цель и критерий успеха

**Цель.** Ученик понимает, что происходит между `http.Client.Do` и ответом сервера. Понимание должно быть настолько полным, чтобы он мог:
- объяснить, откуда берётся задержка;
- правильно настроить в Go пул соединений и таймауты;
- найти сетевую проблему с помощью `ss`, `tcpdump`, Wireshark, `dig` и `curl`.

**Критерий успеха:**
- каждая лабораторная запускается по инструкции урока и даёт вывод, совпадающий с показанным в уроке по смыслу и порядку величин;
- после модуля ученик отвечает на мини-интервью без книг;
- ссылки «подробно — модуль 0b» из уроков 0.3 и 0.4 ведут на реально существующие разделы.

### 3.2 Окружение

**Образ (`Dockerfile`):**
- основа `golang:1.26.9-trixie` с закреплённым тегом;
- `apt` ставит `tcpdump`, `iproute2`, `curl`, `dnsutils`, `openssl`, `procps`;
- лабораторные собираются внутри образа.

**`compose.yaml`:**
- сервисы `server`, `client` и `dns` (`coredns/coredns` с закреплённым тегом) в одной bridge-сети;
- у `server` и `client` `cap_add: [NET_ADMIN, NET_RAW]` — для `tc` и `tcpdump`;
- `client` использует `dns` как резолвер (`dns:` в Compose);
- тома: `./captures` в контейнерах для записей.

**`netem.sh <delay> <loss>`.** Применяет `tc qdisc replace dev eth0 root netem delay <delay/2> loss <loss>` на `server` и `client`, поэтому RTT равен `<delay>`. Команда `./netem.sh off` снимает настройки.

**Запуск.** Все команды в уроках выглядят как `docker compose -f labs/0b/compose.yaml exec client …`. README перечисляет их по урокам.

### 3.3 Код

- **Стандарт.** §2.5 основной спецификации и стандарт пользователя: `context` первым аргументом во всём, что ходит вовне; таймауты везде; graceful shutdown по SIGINT/SIGTERM; обёртка ошибок через `%w`; `slog`; параметры — флагами.
- **Без слоёв.** Раскладка domain/usecase/adapters не применяется: это утилиты с одним источником данных. Логика выносится в функции, которые можно тестировать, например подсчёт перцентилей и статистики потерь.
- **Тесты.** Табличные, на чистую логику; сетевые части тестируются через `net.Pipe`/`httptest`, где это даёт смысл.
- **В уроках** код показывается фрагментами из реальных файлов через `<<< @/../labs/0b/cmd/…/main.go#регион`, где регионы размечены `// #region имя` / `// #endregion имя`.

## 4. Движок: песочницы

### 4.1 Тип `Simulation<S, A, F>`

В `viz/core/types.ts` добавляется:

```ts
export interface Simulation<S, A, F = S> {
  initial: () => S
  apply: (state: S, action: A) => S
  steps: (state: S) => readonly Step<F>[]
}
```

- `F` — состояние кадра, если кадры отличаются от состояния песочницы (например, TCP: настройки и потери → кадры по тикам). Сцена хранит текущее состояние песочницы. Действие пользователя даёт новое состояние через `apply`, затем `steps` даёт шаги для `Player`.
- `Player` при смене шагов сбрасывается — это уже работает.
- Тип, описанный в разделе 4.2 основной спецификации как вводимый «в модуле 2.5», появляется здесь. Раздел 4.2 обновляется.

### 4.2 Песочницы модуля

1. **`tcp`.**
   - Модель: отправитель с окном N сегментов, получатель с кумулятивным ACK, RTT в тиках.
   - Повторы: быстрый повтор после трёх дублирующих ACK и повтор по RTO.
   - Действия: «потерять сегмент k», «потерять ACK k», «сброс», размер окна 1–8.
   - **Упрощения, явно названные в уроке:** нет SACK, нет точной формулы RTO, нет slow start внутри песочницы (он объясняется отдельно).
2. **`pool`.**
   - Расчёт таймлайна: запросы × (новое соединение? 1 RTT TCP + 1 RTT TLS) + 1 RTT запрос/ответ; пул ограничивает число соединений.
   - Ввод: RTT, число запросов, параллельность, размер пула, TLS вкл/выкл.
   - Вывод: диаграмма по соединениям, общее время, число рукопожатий.
3. **`lanes`.**
   - Три режима: HTTP/1.1 (k соединений, запросы по очереди), HTTP/2 (одно соединение, потоки чередуются в пакетах), QUIC (потоки независимы).
   - Действие: «потерять пакет p».
   - Вывод: какие потоки задержаны и на сколько RTT.
   - **Упрощение, названное в уроке:** нет управления перегрузкой.

### 4.3 Пошаговые плееры

`encapsulation`, `dns`, `cert-chain`, сравнение UDP и TCP — сценарии `Scenario<S>` с отдельными рендерерами.

### 4.4 Общие требования

- **Шаги и подписи.** Подписи на русском, термины — сегментами с `termId`.
- **Тесты.** Расчёты — чистые функции с тестами Vitest: инварианты и контрольные случаи. Например, потеря первого пакета в HTTP/2 задерживает все потоки, а в QUIC — только один.
- **Оформление.** Каждая сцена в `VizFrame`, палитра `--viz-*`, узкая раскладка для 375 px, `prefers-reduced-motion`.

## 5. Глоссарий

Новые термины, если их ещё нет:
- сетевые основы: `socket`, `port`, `mtu`, `encapsulation`, `cwnd` (окно перегрузки), `slow-start`, `retransmission`, `time-wait`, `nagle`, `datagram`;
- DNS: `dns-record`, `ttl`, `resolver`;
- TLS: `certificate`, `ca`, `sni`, `alpn`, `session-resumption`;
- HTTP: `keep-alive`, `connection-pool`, `multiplexing`, `head-of-line-blocking`, `hpack`;
- QUIC и инструменты: `quic`, `zero-rtt`, `netem`, `pcap`.

Существующие `tcp`, `udp`, `tls`, `dns`, `rtt`, `http` переиспользуются и при необходимости дополняются.
