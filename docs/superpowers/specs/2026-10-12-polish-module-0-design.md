# Полировка модуля 0: стиль, глубина, код, полноэкранный режим

- **Дата:** 2026-10-12
- **Статус:** черновик на проверку
- **Подпроект:** 2 (после «Платформа курса + модуль 0»)
- **Основная спецификация:** `docs/superpowers/specs/2026-10-09-course-platform-design.md`. Новые общекурсовые стандарты (2.2 п. 10, 2.3 «Полноэкранный режим», 2.4, 2.5) записаны там. Этот документ описывает, как применить их к модулю 0 и платформе.
- **Бэклог-источник:** `docs/superpowers/backlog-after-module-0.md`

## 1. Цель

Модуль 0 и платформа соответствуют новым стандартам: «Ночной терминал», самодостаточная теория, код уровня прода, полноэкранные визуализации. Все следующие модули пишутся уже на этой основе.

**Критерий успеха:**
- ученик проходит модуль 0, ни разу не открыв книгу ради понимания;
- каждую визуализацию и крупную схему можно открыть на весь экран;
- сайт выглядит как выбранный макет C.

## 2. Визуальный стиль

### 2.1 Тема

- **Цвета.** Тёмная тема по умолчанию (`appearance: 'dark'`). Цвета задаются через переопределение переменных `--vp-c-*` в `course/.vitepress/theme/custom.css` для тёмной и светлой темы:

  | Роль | Тёмная | Светлая |
  |---|---|---|
  | Фон страницы | `#0b1220` | `#ffffff` |
  | Фон блоков | `#0f172a` | `#f8fafc` |
  | Бренд | `#38bdf8` | `#0284c7` |
  | Акцент | `#a3e635` | `#4d7c0f` |
  | Числа | `#fcd34d` на `#3a2a0a` | `#b45309` на `#fef3c7` |

  Контраст текста ≥ 4,5:1 в обеих темах.
- **Шрифты.** Inter и JetBrains Mono через пакеты `@fontsource-variable/inter` и `@fontsource-variable/jetbrains-mono`, подключаются в теме. Внешних запросов нет.
- **Палитра визуализаций** `--viz-*` сохраняет смысл цветов (клиент синий, сервис фиолетовый, БД зелёная, кэш янтарный, брокер бирюзовый, сеть серая). Тёмные значения подбираются под фон `#0b1220`.

### 2.2 Метки частей урока

- **Компонент `<Part kind="…">`.** Цветная метка внутри заголовка раздела: `## <Part kind="theory" /> Теория`.
- **Набор `kind`:** `problem`, `theory`, `viz`, `mistakes`, `tradeoff`, `code`, `selfcheck`, `sources`, `deep`. Цвета постоянные, по макету C (Проблема — роза, Теория — голубой, Визуализация — бирюза, Компромисс — янтарь, Код — серый, Самопроверка — лайм).
- **Оглавление страницы (outline)** показывает текст заголовка без мусора от метки.
- **Все уроки модуля 0** получают метки у разделов верхнего уровня.

### 2.3 Числа

- **Компонент `<N>`** подсвечивает ключевое число: `<N>144 мс</N>`.
- **Необязательный `tone`:** `accent` или `brand`, по умолчанию янтарь.
- **Сколько использовать:** только для чисел, которые урок просит запомнить или сравнить, — в среднем 3–8 на урок.

### 2.4 Mermaid в палитре

- **Тема Mermaid** задаётся `themeVariables` под «Ночной терминал». Отдельно для тёмной и светлой темы.
- **Готовые `classDef`:** `client`, `service`, `db`, `cache`, `broker`, `network`, `deep`. Документируются в `course/viz/README.md`.
- **Все схемы модуля 0** используют эти классы.
- **Mermaid грузится только на страницах со схемами.** Вместо `vitepress-plugin-mermaid` используется собственный компонент, который динамически импортирует `mermaid` в `onMounted`. Блоки ` ```mermaid ` превращаются в этот компонент markdown-плагином.
- **Цель по производительности:** основной чанк сайта без Mermaid.

## 3. Глубина теории

### 3.1 Компонент `<Deep>`

- **Как выглядит.** Раскрывающийся блок «🔬 Под капотом: {title}», по умолчанию свёрнут, внутри — Markdown. В оглавление не попадает.
- **Где ставится.** Сразу после того места основного текста, которое он углубляет.

### 3.2 Аудит модуля 0

Для каждого урока ищутся места, где читателю пришлось бы идти в источник. Каждое закрывается либо в основном тексте, если без этого не понять урок, либо в `<Deep>`. Обязательный минимум:

| Урок | Блоки «Под капотом» |
|---|---|
| 0.1 | Почему активное вспоминание работает (эффект тестирования, кривая забывания) |
| 0.2 | Коррелированные отказы: почему 1 − (1 − a)² — оценка сверху; как считать доступность с зависимостями |
| 0.3 | Цепочка DNS (стаб-резолвер → рекурсивный → корневой → TLD → авторитетный, кэш и TTL на каждом шаге); TCP: состояния, порядковые номера, повтор потерянных пакетов; TLS 1.3: обмен ключами ECDHE и проверка сертификата; fsync: кэш ОС, кэш записи диска, защита от потери питания |
| 0.4 | Локальность и кэш-линии (почему последовательное чтение быстрее); устройство SSD (страницы, блоки стирания, усиление записи); вывод закона Литтла на интуиции |
| 0.5 | Нагрузка на чтение и соотношение чтение/запись; биты и байты в каналах; индексы и накладные расходы хранения |
| 0.6 | Память на одно WebSocket-соединение и что ограничивает число соединений на сервер (файловые дескрипторы, память, порты); fan-out при записи и при чтении на числах |

- **Объём.** Блок «Под капотом» — 150–500 слов.
- **Правила.** Подчиняется 2.2 основной спецификации: термины, числа с источником, никаких искажений.

### 3.3 Источники

- **Формат строки источника:** «Автор, название, глава — что там найти дополнительно».
- **Переход.** Все источники модуля 0 переводятся на этот формат.
- **Правило.** Источник больше не нужен для понимания урока.

## 4. Код

### 4.1 Обработчик в уроке 0.3

Переписывается по 2.5 основной спецификации:
- `http.MaxBytesReader` ограничивает тело запроса;
- `json.Decoder.DisallowUnknownFields`;
- валидация (пустой текст, длина);
- `context.WithTimeout` на вызов use case;
- сопоставление доменных ошибок с HTTP-статусами через `errors.Is`;
- ошибка `Encode` логируется.

Номера строк для `CODE_LINE` обновляются, тест на расхождение фрагмента и `CODE_LINE` остаётся.

Под фрагментом — плашка «⚠️ Упрощено». Она перечисляет, что в настоящем сервисе вынесено в middleware (аутентификация, логирование запросов, метрики) и где это будет (модули 1 и 12).

### 4.2 Остальные фрагменты

- **Каждый Go-фрагмент модуля 0 компилируется.** Проверка: тест или скрипт извлекает Go-блоки из уроков, помеченные `<!-- go-check -->`, и прогоняет через `gofmt -l` и `go vet` в изолированном временном модуле. Фрагменты, которые не являются законченной программой, проверяются с минимальной обвязкой (`package snippet` и импорты), описанной рядом с проверкой.
- **Игнорируемых ошибок нет.**

## 5. Полноэкранный режим

### 5.1 Компонент `<VizFrame>`

- **Кнопка.** Оборачивает визуализацию или схему и добавляет кнопку ⛶ с `aria-label="На весь экран"` или «Выйти из полноэкранного режима».
- **Как включается.** Через Fullscreen API на элементе обёртки. Если API недоступен или отказал, используется класс-оверлей `position: fixed; inset: 0`, блокировка прокрутки страницы и выход по Esc.
- **Что меняется на весь экран:**
  - сцена получает всю высоту;
  - `Player` ставит код справа от схемы, если ширина ≥ 900 px;
  - шрифт пояснения крупнее.
- **Клавиши.** ← → и пробел работают, фокус переносится внутрь обёртки.
- **Узкий экран в портретной ориентации.** Подсказка «Поверните телефон для лучшего вида», её можно закрыть.
- **SSR.** Всё, что трогает DOM, выполняется только на клиенте; слушатели снимаются в `onBeforeUnmount`.

### 5.2 Где используется

- `RequestPath`, `LatencyScale`, `EstimationCalculator`;
- компонент Mermaid (каждая схема получает ⛶);
- карта курса в уроке 0.1 — её мелкость на телефоне решается именно так.

## 6. Попутные пункты из бэклога

1. **Подписи шагов с терминами.**
   - `Step.caption` принимает строку или массив сегментов `{ text: string; termId?: string }`.
   - `Player` рендерит сегменты с `termId` через `<T>`.
   - Тест проверяет, что все `termId` во всех сценариях есть в `terms.yaml`.
   - Сценарий `request-path` переводится на сегменты для RTT, TLS-терминации, fsync и других терминов.
2. **Лёгкие подсказки терминов.**
   - Отдельный data loader отдаёт `T.vue` только `term`, `en` и `short`.
   - `longHtml` грузится только на странице глоссария.
3. **Глоссарий.**
   - Алфавитный указатель (кириллица, затем латиница) с якорями.
   - Пояснение в начале страницы о порядке.
4. **Доступность подсказок.**
   - Подсказка с интерактивной ссылкой получает `role="dialog"`/`aria-*` по смыслу, а не `role="tooltip"`.
   - Esc не сбрасывается уходом мыши, пока фокус внутри.
5. **Легенда** `viz/README.md` дополняется цветами видов задержек и классами Mermaid.
6. **Мелочи из бэклога, относящиеся к затронутым файлам:**
   - литералы NBSP заменяются на ` `;
   - `seek(NaN)` → 0;
   - ошибка разбора YAML во frontmatter называет файл.

## 7. Вне рамок

- новые уроки и модуль 0b (следующий подпроект, уже по этим стандартам);
- деплой;
- переработка движка сверх пункта 6.1.

## 8. Проверка готовности

- **Сборка и тесты.** `npm test`, `npm run typecheck` и `npm run build` проходят. Предупреждения о размере чанка из-за Mermaid больше нет.
- **Внешний вид в Playwright** на ширине 375 и 1280 px, в тёмной (по умолчанию) и светлой теме, для всех страниц модуля 0, `/` и `/glossary`:
  - нет горизонтальной прокрутки;
  - метки частей урока видны;
  - схемы в палитре;
  - контраст текста ≥ 4,5:1 (выборочная проверка через `getComputedStyle`).
- **Полноэкранный режим** проверен для каждой визуализации и для карты курса: вход, клавиши, выход по Esc, оверлей-фолбэк (эмуляция отказа Fullscreen API).
- **Глубина.** Каждый урок модуля 0 содержит блоки «Под капотом» из таблицы 3.2. Ревьюер подтверждает, что для понимания урока не нужен внешний источник.
- **Код.** Все Go-фрагменты модуля 0 проходят `gofmt -l` и `go vet`.
