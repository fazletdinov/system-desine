# Мерка интерактива, PR 2: модуль 0 — план

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** довести схемы и термины модуля 0 (уроки 0.1–0.6) до мерки. Шкала задержек получает реальные числа с машины автора из новой лабы `labs/0-4`.

**Architecture:**
- Песочницы вида B (`LatencyScale`, `EstimationCalculator`) получают объяснение по клику. Это та же связка `Explain<S>` + `ExplainPanel`, что в сцене B-tree, но без `Player`. Общая обвязка выбора элемента выносится в `viz/core` (первая задача).
- Сцена-поток `RequestPath` получает только контекст, термины и подпись «модель, не замер».
- Числа задержек — новая лаба `labs/0-4`: Go-бенчмарки памяти, `fio` и `pg_test_fsync` в контейнерах, пинг между контейнерами. Результаты лежат в `labs/0-4/results/*.txt`, из них берётся столбец «у автора».
- Тексты уроков: термины по §7.1 спецификации и правки точности из инвентаризации.

**Tech Stack:** VitePress 1.6, Vue 3.5, TypeScript 5.9, vitest; Go (модуль `labs/`), Docker Compose, `fio`, `pg_test_fsync` (образ `postgres:18.6`).

**Spec:** `docs/superpowers/specs/2026-10-22-viz-standard-design.md` (§3 мерка, §6 доводка модулей, §7 термины).
**Inventory (входные данные, обязательны к прочтению исполнителем):** `.superpowers/inventory/module-0.md` — таблицы схем, терминов, точности и контраста с номерами строк. План ссылается на её пункты (`1.3 M3`, `2.1`, `T4` и т. д.); тексты объяснений, списки терминов и правки берутся оттуда.

## Review Focus

1. Песочница в колонке урока (≈690 px) и в полноэкранном `VizFrame`: панель объяснения не ломает раскладку ни там, ни там; клик по элементу, затем смена входа (масштаб, пресет, слайдер) — панель показывает актуальные числа, а не устаревшие. Тест «Здесь» на числах — Task 3/4.

3. Лаба на другой машине: `scenario.sh` проверяет порядок величины, а не точное число; без Docker / без прав на `O_DIRECT` падает с понятным сообщением. Проверка — Task 2.
4. Числа «у автора» в шкале совпадают с файлами `labs/0-4/results/*.txt` (не переписаны руками с ошибкой). Тест — Task 3.
5. `<T>` на первом вхождении не ломает Markdown (inline-код, заголовки, таблицы). Проверка — `check:refs` + сборка, Task 5.
