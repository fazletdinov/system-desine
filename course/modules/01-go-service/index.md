# Модуль 1. Сервис на Go

Первая версия мессенджера почти всегда пишется «как получится»: обработчик запроса сам разбирает JSON, ходит в SQL и шлёт уведомление. Работает, пока не придёт время сменить базу, добавить второй транспорт или поменять формат API: тогда переписывать приходится всё. В этом модуле мы строим сервис так, чтобы бизнес-логика не зависела от хранилища, транспорта и формата API и жила дольше любого из них.

В этом модуле вы:

- разложите сервис по слоям и сможете объяснить правило зависимостей и зачем порт объявляют там, где его используют;
- смоделируете домен мессенджера и научитесь держать инварианты там, где их нельзя обойти;
- освоите ошибки и `context` в Go, включая отмену работы по всей цепочке вызовов;
- напишете use case'ы, отличите фейк от мока и проверите хранилище контрактным тестом;
- соберёте тонкий HTTP-адаптер и запустите сервис, который можно потрогать через `curl`.

Код живёт в каталоге `messenger/`, а каждый урок заканчивается тегом `m01-lNN`: чтобы увидеть код ровно в состоянии после урока 3, выполните `git checkout m01-l03`.

Уроки модуля:

1. [Зачем сервису архитектура](./01-architecture) — слои, правило зависимостей, `depguard`, ADR.
2. [Домен: правила, которые нельзя нарушить](./02-domain) — сущности, value objects, инварианты.
3. [Ошибки в Go: сигналы, обёртки и границы](./03-errors) — `errors.Is/As`, `%w`, `ValidationError`.
4. [Use case'ы и порты: сценарии отдельно от деталей](./04-usecases) — порты у потребителя, оптимистическая блокировка.
5. [context: как остановить работу, которая больше не нужна](./05-context) — отмена и сроки по всей цепочке.
6. [Тесты: что проверять и на каком уровне](./06-tests) — фейки и моки, контрактные тесты, `-race`.
7. [Тонкий HTTP-адаптер и сборка приложения](./07-http-adapter) — DTO, маппинг ошибок, корень композиции, `curl`.

Уроки частей 1b и 1c появятся позже, нумерация продолжится с 1.8: в 1b — проектирование REST API (формат ошибок, пагинация, версии, ключ идемпотентности, OpenAPI) и JWT вместо заглушки `X-User-ID`, в 1c — Docker изнутри, CI на GitHub Actions и мини-интервью по модулю.
