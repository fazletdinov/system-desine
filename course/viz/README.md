# Визуальный язык курса

Все визуализации используют одни и те же цвета и обозначения. Цвета задаются только через переменные из `palette.css` — для светлой и тёмной темы.

| Сущность | Переменная | Обозначение |
|---|---|---|
| Клиент (телефон, браузер) | `--viz-client` | прямоугольник со скруглением |
| Сетевой узел (DNS, балансировщик) | `--viz-network` | прямоугольник со скруглением |
| Сервис (Go) | `--viz-service` | прямоугольник со скруглением |
| База данных | `--viz-db` | прямоугольник со скруглением |
| Кэш (Redis) | `--viz-cache` | прямоугольник со скруглением |
| Брокер (Kafka) | `--viz-broker` | прямоугольник со скруглением |
| Запрос | `--viz-request` | движущийся круг |
| Ответ | `--viz-response` | движущийся круг |
| Ошибка | `--viz-error` | движущийся круг + красная рамка узла |
| Активный узел | `--viz-active` | толстая рамка |
| Связь | `--viz-edge` | линия |
| Второстепенный текст | `--viz-muted` | подписи, пояснения: светлая тема `#5f6b7e` (≥ 4,5:1 и на фоне плеера `#f6f6f7`), тёмная — мятный `#a8d8bb` |
| Адрес / ссылка в структуре | `--viz-addr` | TID, «→ блок N» (в тёмной теме тёплый жёлтый) |
| Совпало с условием | `--viz-hit-bg` / `--viz-hit-text` | заливка записи или строки + текст на ней; только для «совпало», не для подсказок (те — пунктир `--viz-muted` без заливки) |

Правило текста: синий — только для рамок и линий; второстепенный текст — `--viz-muted`, адреса — `--viz-addr`. Заливка «совпало с условием» — `--viz-hit-bg` с текстом `--viz-hit-text`. Контраст каждого текстового токена ≥ 4,5:1 проверяет `viz/core/contrast.test.ts`.

Правила:
- у каждого шага есть пояснение на русском;
- анимация отключается при `prefers-reduced-motion`;
- новая работа проверяется только на компьютере: ширина 1280 px, обе темы; текст внутри SVG на экране — не меньше 12 px (подписи — не меньше 11 px). Правило «375 px: `font-size` ≥ 12 × ширина `viewBox` / 290, иначе отдельная узкая раскладка, как в `RequestPathView.vue`» осталось от старых схем — для новых его не проверяем;
- всё, что трогает DOM или GSAP, выполняется только на клиенте (`onMounted`, `watch` без `immediate`).

## Мерка

Что обязательно у схемы, зависит от её вида (полностью — `docs/superpowers/specs/2026-10-22-viz-standard-design.md`, §3).

| Требование | A. Сцена по шагам (`Player`) | B. Песочница | C. Статика (Mermaid, `Shot`, SVG без шагов) |
|---|---|---|---|
| M1. Контекст: какой запрос / действие мессенджера / код показаны — видно на схеме или прямо над ней | ✔ | ✔ | ✔ |
| M2. Карточка шага: что происходит, какая структура, что читается, почему так | ✔ | — (вместо неё M3 для каждого управляющего элемента) | — |
| M3. Клик по элементу → объяснение: что это, роль, что хранит, связи, что с ним в текущем шаге | ✔ | ✔ | — |
| M4. Термины: первое упоминание — через `term()` / `<T>`; нет в глоссарии — добавить | ✔ | ✔ | ✔ (в тексте вокруг) |
| M5. Честность: учебные данные подписаны; реальные числа — с источником из `labs/`; упрощения перечислены | ✔ | ✔ | ✔ |
| M6. «Проверь себя» после ключевых шагов, ответ скрыт до нажатия | ✔ (1–3 на сцену) | по желанию | — |
| M7. Читаемость: текст ≥ 4,5:1 к фону в обеих темах, подписи не перекрываются на 1280 px, второстепенный текст в тёмной теме не синий | ✔ | ✔ | ✔ |
| M8. Два вида «схема / подробно» — только где у структуры есть поверхность и внутренности | по смыслу | по смыслу | — |

Виды A и B делятся ещё на два подвида:
- **механизм** — схема показывает, как что-то устроено внутри (индексы, MVCC, WAL, планировщик Go, TCP, cgroups): обязательны все требования столбца;
- **поток** — путь или последовательность без внутренностей (запрос через слои, цепочка ошибок, этапы CI): обязательны только M1, M4, M5, M7.

Спорную схему считаем механизмом. Эталон механизма — `scenes/BtreeInside.vue` (урок 2.5).

## Карточка, объяснение, вопрос

Всё необязательно: шаг без новых полей рисуется как раньше.

- **Карточка шага (M2).** Поле `card` у `Step<S>` (`core/types.ts`): `{ what, uses, reads, why }` — что происходит, какая структура работает, что читается или получается, почему так. Каждая часть — `Caption`, поэтому термины через `term()` работают. `Player` сам рисует `StepCard` под подписью шага; `caption` остаётся короткой строкой для `aria-live`.
- **«Проверь себя» (M6).** Поле `quiz`: `{ question, answer }`, оба `Caption`. `Player` рисует `StepQuiz`: ответ скрыт до нажатия и снова скрывается при смене шага.
- **Объяснение по клику (M3).** Сцена даёт чистую функцию `Explain<S> = (id, step) => Explanation | null` (`core/explain.ts`): заголовок, вид, разделы, «Здесь» (что с элементом в текущем шаге), «В настоящей системе». Рендерер помечает кликабельные элементы стабильным id (`data-explain`) и шлёт событие `select(id)`. Сцена держит `selected`, сбрасывает его по событию `step` плеера и кладёт `ExplainPanel` в слот `side`:

```vue
<Player :steps="steps" label="…" @step="selected = null">
  <template #default="{ step }"><MyView :frame="step.state" :selected="selected" @select="(id) => (selected = id)" /></template>
  <template #side="{ step }"><ExplainPanel :explanation="explain(selected ?? step.state.focus, step)" /></template>
</Player>
```

Без клика панель объясняет то, о чём шаг (`focus` в состоянии кадра). Со слотом `side` и контейнером шире 900 px панель встаёт справа от холста, уже — под ним. Термины в карточках, вопросах и объяснениях тесты сцены сверяют с глоссарием (`stepTermIds`, `explanationTermIds`).

## Классы Mermaid

В блоках ```` ```mermaid ```` с `flowchart`/`graph` доступны классы узлов. Пример: `A[Телефон]:::client --> B[Go-сервис]:::service`.
Блоки `classDef` добавляются автоматически, писать их в уроке не нужно. Цвета живут в `viz/core/mermaid-palette.ts` (Mermaid не читает CSS-переменные).

| Класс | Смысл |
|---|---|
| `client` | клиент: телефон, браузер |
| `service` | сервис на Go |
| `db` | база данных |
| `cache` | кэш (Redis) |
| `broker` | брокер сообщений (Kafka) |
| `network` | сетевой узел: DNS, балансировщик |
| `deep` | углубление: необязательный материал (пунктирная рамка) |
| `error` | ошибка, авария: паника, отказ (красная рамка, `--viz-error`) |

## Шкала задержек

| Уровень | Переменная |
|---|---|
| `cpu` | `--viz-service` |
| `memory` | `--viz-cache` |
| `disk` | `--viz-db` |
| `network` | `--viz-network` |

Здесь цвет означает уровень иерархии памяти, а не тип узла: диск окрашен как БД, потому что обычно именно там живут данные, но это не «база данных» на схеме.

## Флейм-граф

| Чей код в блоке | Переменная |
|---|---|
| мессенджер (`messenger/…`, `main`) | `--viz-service` |
| стандартная библиотека | `--viz-client` |
| рантайм Go (`runtime`, `internal/runtime/…`, ассемблер) | `--viz-network` |
| сторонний модуль (`golang.org/x/…`, `github.com/…`) | `--viz-cache` |
| «прочее» — слитые мелкие стеки | пунктир `--viz-muted` |

Совпадение поиска — толстая рамка `--viz-text`, а не цвет: цвет уже занят смыслом «чей код».

## Полноэкранный режим

- Каждая сцена и схема оборачивается в `VizFrame` (`viz/components/VizFrame.vue`), кроме `BtreeInside`: у неё превью в колонке и свой оверлей на весь экран (схеме нужна ширина ~1080 px). Логика выбора режима — в чистом модуле `viz/core/fullscreen.ts`.
- В полноэкранном режиме контейнер плеера шире 900 px, и код встаёт справа сам — через container query.
- Оверлей (`position: fixed` поверх страницы) — запасной вариант для iPhone Safari и для случая, когда браузер отказал в `requestFullscreen`.

## Снимки экрана (`<Shot>`)

Настоящий снимок программы с окнами с пометками, как в книге: `course/components/Shot.vue`, логика — в чистом модуле `shot.ts`.

- Файл — WebP в `course/public/shots/<урок>/`, путь в уроке — от корня сайта: `src="/shots/…"` (base добавляет компонент). Как снимали и как переснять — `course/public/shots/README.md`.
- `:width`/`:height` — размеры файла: из них viewBox пометок; `check:refs` сверяет их с файлом.
- `:marks` — `{ n, x, y, w?, h?, at?, text }`, координаты в процентах от снимка. С `w`/`h` — рамка (левый верхний угол в `x, y`), номер встаёт снаружи рамки; без них `x, y` — центр кружка. `at` (`right`, `left`, `above`, `below`) ставит номер рамки на заданную сторону, если автоматический выбор закрывает соседний текст. `text` — пояснение под снимком с тем же номером, код — в обратных кавычках.
- Цвет пометки — `--course-accent` (подсветка курса), ореол — `--vp-c-bg`: пометка читается и на светлом, и на тёмном снимке.
- Клик по снимку открывает его на весь экран через `VizFrame`; пояснения тогда встают колонкой справа.
